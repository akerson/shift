# Shift — Daily Factory Puzzle

> Working title. Alternatives: Beltle, Factordle, Throughput, Line Check. Avoid "Factorio" / "Satisfactory" in the name (trademarks). Check GitHub and domain availability before committing.

## Concept

Each day there's one 20×20 factory floor. Raw material sources sit on the left, demand ports on the right, and terrain gets in the way. Players build belts and multi-tile machines to meet every demand rate, then optimize the design. Belts can't cross, so crossings are handled by mixing items onto one belt and splitting them again with sorters. The puzzle is generated automatically every day and is the same for everyone.

## Rules (v1)

### Parts

| Part | Size | Behavior |
|---|---|---|
| Belt | 1×1 | Moves items 1 tile per tick, holds 1 item, directional |
| Merger | 1×1 | 2–3 inputs → 1 output, alternates between inputs |
| Splitter | 1×1 | 1 input → 2–3 outputs, alternates between outputs |
| Sorter | 1×2 | Mixed input → chosen item exits forward, everything else exits the side |
| Smelter | 2×2 | 1 input, 1 output on the opposite side |
| Press | 2×2 | 1 input, 1 output on an adjacent side |
| Assembler | 3×3 | 2 inputs on different sides, 1 output |
| Refinery | 3×2 | 1 input, 2 outputs (product + byproduct) |

### Fixed elements (placed by the generator)

- **Sources:** emit one item type at a fixed rate.
- **Demand ports:** consume one item type and have a target rate.
- **Disposal ports:** accept anything, for byproducts.
- **Terrain:** blocked tiles.

### Rules

- No underground belts. Belts cannot cross.
- Machines can be rotated, but their port layout is fixed per type.
- A machine pulls items from a belt that ends at one of its input ports. No inserters.
- Machines have a small input buffer (typically 2 of each ingredient). When the output is blocked, the machine stalls.
- Belts, mergers, and sorters carry at most 1 item per tick.
- An item arriving at a port that won't accept it jams that belt.

### Passing and scoring

- **Pass:** after a warm-up period, every demand port meets its rate across a 200-tick measurement window, with no jams or overflow.
- **Scores:**
  - **Footprint:** area of the bounding box around everything the player placed.
  - **Cost:** sum of part costs (machines expensive, sorters medium, belts cheap).
  - **Latency:** tick at which the first product arrives.
- **Par:** the reference builder's score on each metric.

## Tech stack

- **TypeScript + Vite**, deployed as a static site to GitHub Pages.
- **Rendering:** Canvas 2D to start; PixiJS only if item animation gets slow.
- **Simulation:** pure, headless TypeScript module, integer math only, no DOM. Shared by the game, the generator, and the tests, so scores are reproducible.
- **RNG:** seeded generator (sfc32 or mulberry32), seeded from date string + generator version.
- **Tests:** Vitest, with heavy coverage of the simulation.
- **No backend in v1.** Stats and streaks live in localStorage.

## Daily pipeline

Puzzles are generated by a **GitHub Action**, not in the player's browser.

- A nightly cron job runs the generator in Node and commits `puzzles/YYYY-MM-DD.json` for **7 days ahead**, so a few failed runs go unnoticed by players.
- Past puzzles are frozen as committed files. The generator can be improved later without changing old puzzles or invalidating old scores.
- No time limit in the Action, so the generator can run heavier checks than a browser could.
- The client fetches today's file using the player's local date (like Wordle).

## Generator stages

1. **Recipe tree.** Pick a target product and build its ingredient tree from the fixed catalog, 2–4 tiers deep. Choose craft times so machine ratios are small integers (2:3, 3:4).
2. **Rates.** Set source and demand rates. Keep total load within belt capacity, or deliberately exceed one belt's capacity on harder days.
3. **Floor.** Place sources on the left edge, demand and disposal ports on the right edge, and terrain clusters. On harder days, order sources so lines are forced to cross.
4. **Reference builder.** Calculate machine counts, place machines greedily, route belts with A* without crossings. When blocked, insert a merger–sorter pair. If it still can't finish, discard and try the next seed.
5. **Validation.** Run the reference solution through the real simulation and confirm it passes.
6. **Difficulty filter.** Score candidates on tree depth, forced crossings, terrain density, and number of products. Keep the first that fits the day's band. Monday easiest → Saturday hardest; Sunday is "weird" (an unusual twist).
7. **Output.** Write puzzle JSON: floor, catalog subset, rates, par scores, generator version, seed.
